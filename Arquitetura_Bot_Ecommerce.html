1. Visão Geral do Projeto

Objetivo

Montar um sistema integrado que sincroniza catálogo (Bling → Mercado Livre + Site), com bot automático respondendo perguntas contextualizadas com dados do produto.

Componentes Principais

  • ✓ Banco de dados centralizado (PostgreSQL)
  • ✓ Bot respondedor automático (Node.js + Groq IA)
  • ✓ Sincronização Bling ↔ Banco ↔ Mercado Livre
  • ✓ Site/vitrine (Tray existente OU Next.js novo)
  • ✓ Painel de administração

Contexto Atual

  • Cliente usa: Bling (ERP), Mercado Livre (vendas), Tray (e-commerce)
  • Desafio: Sem acesso ao código-fonte da Tray, precisa sincronizar dados
  • Solução: Banco de dados central que medeia todas as integrações

2. Opção A: Integração com Tray (SaaS Existente)

Descrição

Manter a plataforma Tray existente e integrar o bot + banco de dados via APIs.

Arquitetura

Banco de Dados Central ↓↑ TRAY (SaaS) ←→ Bling API ←→ Mercado Livre API │ Bot Server

Vantagens

  • ✓ Cliente continua usando Tray (familiarizado)
  • ✓ Sem necessidade de reescrever site
  • ✓ Bot pode estar integrado via webhook

Desvantagens

  • ✗ Tray é caro (R$200–500/mês)
  • ✗ API Tray é limitada (nem tudo customiza)
  • ✗ Tray não redireciona fácil para Mercado Livre
  • ✗ Sincronização Bling ↔ Tray é complexa
  • ✗ Pouco controle sobre fluxo de dados
  • ✗ Custo total mais elevado (Tray + Bot + Banco)

Custo Mensal

  • Tray: R$200–500
  • Banco + Bot: R$60
  • Total: R$260–560/mês

3. Opção B: Site Novo em Next.js ⭐ RECOMENDADO

Descrição

Construir um novo site e-commerce (Next.js) que sincroniza com Bling e Mercado Livre, com bot integrado nativamente.

Arquitetura

Hostinger VPS ├─ Next.js App (site + admin) │ ├─ /produtos (catálogo) │ ├─ /admin (painel) │ └─ /api (bot webhook) └─ PostgreSQL (banco local)

Vantagens

  • ✓ 100% customizável (controle total)
  • ✓ Custo menor (R$60/mês vs R$200+ Tray)
  • ✓ Sincronização Bling perfeita
  • ✓ Bot integrado nativamente
  • ✓ Redireciona fácil para Mercado Livre
  • ✓ Escalável sem limitações de plataforma
  • ✓ Dados sempre atualizados em tempo real

Desvantagens

  • ✗ Precisa implementar do zero (~2-3 semanas MVP)
  • ✗ Cliente não usa mais Tray (migração necessária)

Custo Mensal

  • Hostinger VPS: R$60
  • APIs (Groq, Gemini, ML, Bling): Grátis
  • Total: R$60/mês (+ R$80 domínio one-time)
⭐ Por que Opção B é melhor:
Economia de R$2.320–5.920/ano + controle total + sincronização perfeita + bot nativo.

5. Arquitetura Técnica Detalhada (Opção B)

Stack Tecnológico

Camada Tecnologia Por quê
Servidor Web Node.js 20 LTS + Fastify Leve, ótimo para I/O assíncrono
Framework Next.js 15 (App Router) SSR, API routes, full-stack
Banco de Dados PostgreSQL 15 + pgvector Relacional + busca vetorial (RAG)
IA Generativa Groq API (Llama 3.3 70B) Grátis: 14.400 req/dia, <1s resposta
Embeddings Google Gemini text-embedding Grátis: 1.500 req/min
Autenticação ML OAuth 2.0 (Mercado Livre) Padrão oficial, token auto-renova
Hosting Hostinger VPS 2vCPU/4GB ~R$60/mês, suficiente para MVP

Módulos do Servidor

  • 🔌 Webhook Receiver: Recebe notificações do ML em tempo real
  • 🔍 ML API Client: Busca pergunta + dados do produto
  • 📚 RAG Engine: Busca contexto (histórico Q&A similar)
  • 💭 Prompt Builder: Monta prompt com contexto completo
  • 🧠 Groq Client: Envia para IA, recebe resposta
  • 📤 Answer Poster: Posta resposta no ML via API
  • 💾 Database Logger: Salva Q&A + gera embedding
  • ⚙️ Sync Manager: Sincroniza Bling ↔ Banco ↔ ML

6. Modelo de Dados (PostgreSQL)

Tabelas Principais

• products (Catálogo sincronizado)

id | sku | ml_item_id title | description | price | cost category | image_url | sync_status | last_synced_at

• inventory (Estoque em tempo real)

product_id | quantity | reserved | last_updated

• qa_history (Histórico de perguntas/respostas)

id | product_id | question | answer embedding (vector 768D) | answered_at | status

• ml_credentials (Tokens de autenticação - encrypted)

seller_id | access_token | refresh_token | expires_at

• sync_jobs (Log de sincronizações)

id | job_type | status | error_message | last_run_at

7. Fluxos de Dados

Fluxo 1: Sincronização Inicial (Dia 1)

  1. Cliente fornece credenciais Bling + OAuth Mercado Livre
  2. Bot faz import inicial: Bling → Banco local
  3. Bot valida: estoque, preços, descrições
  4. Site fica online: seu-site.com

Fluxo 2: Sincronização Contínua (Daily)

  1. Job 1 (a cada hora): Bling → Banco (produtos, preços, estoque)
  2. Job 2 (a cada 6h): Banco → Mercado Livre (atualiza anúncios)
  3. Site sempre mostra dados frescos

Fluxo 3: Pergunta no Mercado Livre → Resposta Automática

Comprador pergunta ↓ ML envia webhook (POST /webhook/questions) ↓ Bot valida HMAC signature ↓ Bot busca: pergunta + produto (ML API) ↓ Bot consulta: descrição + estoque (banco local) ↓ Bot consulta Bling: specs técnicas (opcional) ↓ RAG busca: 3-5 Q&As similares (pgvector) ↓ Groq gera resposta contextualizada (<1s) ↓ Bot posta resposta no ML (API) ↓ Bot salva Q&A + embedding no banco ↓ Comprador recebe resposta (<2s total)
